# PDF-Redactify

**PDF 속 개인정보를 검출하여 블랙마킹하는 길고 번거로운 업무를 최대한 자동화한 데스크톱 앱입니다.**

개인정보 종류별 자동검출, 사용자 수정 및 추가 검출을 거쳐 검은 박스로 가린 공개용 PDF 파일을 생성합니다. 가려진 정보는 추출하거나 되살릴 수 없도록 처리됩니다. 

> * 자동검출은 문서 내 텍스트 정보를 근거로 하여 `정규식`+`체크섬`+`문맥어(앵커)`+`위치관계`를 종합적으로 판단하여 실행됩니다.
> 
> * 일부를 제외하면 사실상 100% 정확도로 각종 개인정보의 위치 범위와 유형을 판정하는 것은 불가능합니다. 또한 스캔 PDF라면 검출 정확도가 절대적으로 OCR 품질에 좌우됩니다. 
> 
> * 이 앱은 텍스트 위치 오차, 오인식 등이 혼합된 `저품질의 OCR 상황을 고려`하여 최대한 Fuzzy matching 로직을 보완하고, 최종 컨펌자로서 **사용자가 최대한 신속하게 확인, 수정할 수 있도록 편이성을 높이는 데에 주안점**을 두었습니다.

## 주요 기능

- **PDF 뷰어** — 수백 쪽의 문서도 비교적 부드럽게 넘겨볼 수 있도록 경량화했으며, 북마크(목차), 확대/축소, 페이지 넘김 등 기본적인 뷰어의 기능을 제공합니다.
- **개인정보 자동 검출 및 프리뷰 / 목록관리** — 문서 내의 텍스트 정보와 위치관계를 분석하여 개인정보 유형별로 투명한 박스로 가리고 목록으로 보여줍니다. (대상 유형과 기준은 아래 [개인정보 검출 기준](#개인정보-검출-기준) 참고)
- **사용자 직접 지정** — 자동검출 로직에서 누락된 정보들을 사용자가 직접 가릴 수 있습니다. 블랙마킹 박스의 이동, 크기 조정, 삭제도 마우스 또는 키보드 조작으로 최대한 간편하게 할 수 있습니다.
- **검출 제외 구역 설정** — 사용자가 페이지별로 개인정보 출현 가능성이 낮은 가장자리 영역을 모든 자동/수동 검출에서 제외할 수 있습니다. 
- **블랙마킹 정보 내보내기/가져오기** — 엑셀파일로 현재 문서의 블랙마킹 지정 내역을 내보낼 수 있으며, 이 엑셀파일로부터 동일한 문서의 원본(clean version)에 언제라도 간편하게 블랙마킹을 적용할  수 있습니다.
- **블랙마킹(Redaction) 적용 파일 생성** — 원본은 보존하고, 개인정보를 블랙마킹한 새 PDF를 생성합니다. 이때, 원본의 스펙을 검사하여 `동일 또는 최소한의 용량 증가`로 `거의 동일한 품질`의 블랙마킹 버전이 생성되도록 인코딩합니다.

## 설치 방법

[**릴리스 페이지**](https://github.com/bjorkii/PDF-Redactify/releases)에서 사용 OS에 맞는 파일을 내려받으세요.

> [!WARNING]
> 
> 이 앱은 개발자 서명·공증을 받지 않은 무료 배포본입니다. 그래서 처음 실행할 때 OS가
> "확인되지 않은 앱"으로 차단합니다. 아래 절차를 최초 1회만 적용하면 이후부터 문제 없이 실행됩니다.

### macOS

1. `PDF-Redactify_x.y.z_aarch64.dmg`를 열고, 앱을 **응용 프로그램** 폴더로 드래그합니다.

2. macOS 15 Sequoia 이전 버전까지는 `우클릭` → `열기`를 누르면 정상 동작할 수도 있습니다. 그러나 이후의 최신 버전이라면 아래 방법 중 하나를 따르세요.
   
   - **터미널에 아래 명령줄을 붙여넣고 엔터 (가장 확실):**
     
     ```bash
     xattr -dr com.apple.quarantine /Applications/PDF-Redactify.app
     ```
   
   - 앱을 한 번 실행해 차단 메시지가 팝업된 후 → **시스템 설정 → 개인정보 보호 및 보안** → 맨 아래 "PDF-Redactify을(를) 확인 없이 열기" 클릭 → 다시 실행.

### Windows

1. `PDF-Redactify_x.y.z_x64-setup.exe`(설치 프로그램)를 실행해 설치합니다.

2. 코드 서명이 없어 SmartScreen이 "알 수 없는 게시자" 경고를 띄울 수 있습니다. 이때는 **추가 정보 → 실행**을 선택하세요.
   
   > [!CAUTION]
   > 
   > 만일 설치파일 다운로드를 시도했을 때 '신뢰할 수 없는 파일' 문구와 함께 진행되지 않을 경우, 아래 방법에 따르면 됩니다.
   > 
   > - 안내 문구 우측의 옵션을 열어 `유지` 선택
   > - 새 창에서 삭제 버튼 옆 옵션표시를 눌러 `그래도 계속` 선택

### 소스에서 빌드

* 직접 빌드하려면 [Node.js](https://nodejs.org/)(LTS 권장), [Rust](https://www.rust-lang.org/tools/install) 툴체인, Tauri v2 [플랫폼별 준비물](https://tauri.app/start/prerequisites/)이 필요합니다.

```bash
npm install                 # 의존성 설치
npm run setup:pdfium        # pdfium 라이브러리 다운로드(플랫폼 자동 감지)
npm run tauri dev           # 개발 모드 실행
npm run tauri build         # 배포용 번들 빌드
```

* 테스트: `npm test`(프론트엔드, Vitest) / `cargo test --manifest-path src-tauri/Cargo.toml`(백엔드, Rust).

## 개인정보 검출 기준

텍스트의 **형식**, **체크섬**(계산식 검증), 그리고 **주변 문맥 단어**(anchor)를 함께 보고 후보를 찾습니다. 체크섬이 맞지 않아도(OCR 오인식·최신 발급분 등) 후보를 버리지 않고 신뢰도(confidence 점수)만 낮춰 표시하는 **안전 우선(fail-safe)** 방식입니다. 전각 숫자(예: `０１０`)는 반각으로 정규화해 우회를 막습니다.

> [!NOTE] 
> 
> **앵커(anchor)** 란 검출 대상 근처(앞쪽)에 나타나는 라벨 단어입니다. 일부 유형은 오탐이 커서 앵커가 있을 때만 검출하며(아래 "앵커 필수"), 나머지는 앵커가 없어도 검출하되 있으면 신뢰도를 올립니다. 앵커 비교는 대소문자·공백을 무시합니다.

| 구분     | 검출 대상(형식)                                                                                                                                                                                                                        | 판정 방식 · 앵커                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 주민등록번호 | 앞 6자리 + 뒤 7자리 (구분자 `-`·공백 허용)                                                                                                                                                                                                  | 형식 매칭 + **11 modulus 체크섬** 검증. 체크섬이 틀려도(2020년 이후 발급분·OCR 오인식) 버리지 않고 신뢰도만 하향(fail-safe). 앵커(가점): `주민등록번호`, `주민번호`, `주민등록`, `RRN`.                                                                                                                                                                                                                                                                                                      |
| 신용카드번호 | 13~19자리 숫자 (구분자 허용)                                                                                                                                                                                                              | **Luhn 체크섬** + 길이–브랜드 일관성(예: 13자리는 `4`로 시작, 15자리는 `34`/`37`). 앵커(가점): `카드번호`, `신용카드`, `체크카드`, `카드`, `cardno`, `cardnumber`.                                                                                                                                                                                                                                                                                                            |
| 계좌번호   | 은행별로 상이(구분자로 묶인 숫자 그룹)                                                                                                                                                                                                           | **앵커 필수**: `은행`, `계좌`, `계좌번호`, `입금처`, `지급처`. 매치 바로 앞에 은행명(접미사 `은행`, `뱅크`, `금고`, `우체국`, `수협`, `신협`, `축협`으로 끝나는 한글 단어)이 붙어 있으면 은행명까지 함께 블랙마킹.                                                                                                                                                                                                                                                                                            |
| 여권번호   | `[M/S/R/O/D]`+숫자 8, 또는 `[M/S/R/O/D]`+숫자 3+영문 1+숫자 4                                                                                                                                                                              | 형식(허용 문자셋) 검증. 앵커(가점): `여권`, `여권번호`, `여권#`, `한국여권`, `한국여권번호`, `passportno`, `passportnumber`, `passportnumbers`(공백 유무 무관).                                                                                                                                                                                                                                                                                                             |
